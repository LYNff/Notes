# bomb lab 实验心得
## 整体实验概况
我们初始所拥有的是 `bomb` `bomb.c` 文件，但是`bomb.c` 文件缺少`phase`相关函数，我们需要运行`bomb` 这个编译好的二进制文件，拆除对应的 6 个炸弹，因此我们需要找到每个炸弹对应的密码，但是由于缺少源代码，我们只能通过逆向工程，读取机器汇编代码，确定每个未知函数的逻辑！
## 工具
### objdump
我们需要使用`objdump -d bomb` 来反编译`bomb` 这个二进制文件，`objdump -d bomb > bomb.asm` 生成对应的文件方便阅读
### gdb
终端调试工具，本次实验用到的相关指令有：

| 指令          | 全称    | 描述                       |
| ----------- | ----- | ------------------------ |
| r           | run   | 开始执行程序，直到下一个断点或程序结束      |
| q           | quit  | 退出                       |
| ni          | nexti | 执行下一条指令，但不进入函数内部         |
| si          | stepi | 执行当前指令，如果是函数调用则进入函数部     |
| b           | break | 在指定位置设置断点                |
| c           | cont  | 从当前位置继续执行程序，直到下一个断点或程序结束 |
| p           | print | 打印变量的值                   |
| x           |       | 打印内存中的值                  |
| j           | jump  | 跳转到程序制定位置                |
| disas       |       | 反汇编当前函数或指定的代码区域          |
| layout asm  |       | 显示汇编代码视图                 |
| layout regs |       | 显示当前的寄存器状态和他们的值          |
> [!NOTE] 
> `gcc test.c -o test` 生成 ELF 可执行文件，其由 `.text(存放机器指令) .rodata(存放只读数据段) .data(已初始化全局变量) .bss(未初始化全局变量)` 
> `objdump -d bomb` 的意思是只反汇编可执行代码的text段，因此我们无法看到譬如`0x402400`这样的地址，如果想要查看 `.rodata` 可以借助 GDB `x/s 0x402400` 来查看 
## Phase 1 
不要过分纠结 `<strings_not_equal>` 这类名字已经很明显的函数的汇编语言，跳出来看这个函数就是很简单的字符串匹配，我们需要寻找的是 `rsi` 所指向的字符串的内容，使用  `x/s $rsi` 即可找到正确答案
> [!IMPORTANT] 为什么答案储存在 `rsi` 中？
>  `mov $0x402400,%esi` 表示存入对应只读数据段的地址，此地址就储存着对应的答案，是在函数编写的时候就确立的
## Phase 2
读取输入的 6 个元素放入数组中，通过循环判断条件`cmp %rbp,%rbx` 通过不断 `add $0x4,%rbx` 进入循环，判断数组元素之间的关系是否符合后一个元素是前一个元素的两倍
```asm
mov    -0x4(%rbx),%eax
add    %eax,%eax
cmp    %eax,(%rbx)
```
最重要需要理解的就是理解数组的构建和循环过程，借助 gdb 我们可以很轻松的知道我们需要输入的元素的个数 ，阅读 `read_six_numbers` 通过 `x/s $rsi` 去只读段寻找对应的输入格式字符串
## Phase 3
`switch` 语句的实现，需要理解`jmp *0x402470(,%rax,8)`语句，意思是跳转到 `0x402470(,%rax,8)` 所指向的内存地址中，**注意不是跳转到0x402470(,%rax,8)**，是其指向的地址，因此为了查找最终跳转到位置，我们需要在 gdb 中借助`x/10gx`来寻找其对应的跳转地址
> [!IMPORTANT] x/NFU
> N 代表要连续查看的内存单元数，F代表显示格式，U代表单元大小
> 对于 F 常用的有 x(十六进制）、d(有符号十进制)、u(无符号十进制)、a(作为地址解析，gdb会自动将其显示为<函数名+偏移量>的格式)、i(作为汇编指令解析)、s(作为字符串解析)、c(作为单个字符解析)
> 对于 U 常用的是 b(byte) h(halfword) w(word) g(giant word)
## Phase 4
递归函数，阅读`func_4`我们可以看到这是一个二分查找的函数，但是向左查找，返回值会乘以二，向右查找返回值会乘以二加一，但是在`phase_4`中我们需要保证返回值等于0，因此我们需要保证我们输入的值必须小于14，并且要么第一次就找到，要么就一直向左查找。
## Phase 5
字符数组查询，通过输入一个长度为 6 的字符串，读取输入字符串的低四位，在只读区域内寻找我们需要的字符的索引，从而反推需要的字符串是什么从而组成`flyers`
> [!IMPORTANT] Canary Value
> 金丝雀值，用于防止缓冲区栈溢出攻击，在每一轮函数运行时抓取系统产生的随机数，再在函数结尾处进行校验，如果发现修改了，抛出异常，阻止程序继续执行
## Phase 6
链表排序，对于 `mov 0x8(%rdx),%rdx` ，如果我们在gdb中发现 rdx 依旧是一个地址时，就应该知道对应的地址表示一串链表，即表示`node = node->next` ，这一阶段的主要实现是输入 6 个小于 7 的各不相同的数字，然后用 7 减去对应位置的数值，得到排序，这个排序就用于读取的链表的索引，我们需要保证我们读取的前一个值要大于后一个值，所以要根据链表的 6 个结点的大小，推断出读取的顺序，本题的核心就是要知道对应的只读区域存储的是一个已知的链表，通过`x/2gx 地址` 可以读取链表的 `val next`
