# Architecture Lab
## 实验说明
认识了解 `Y86-64` 处理器的汇编语法，学习流水线式 Y86-64 处理器的设计和实现，并对其进行优化，同时优化一个基准测试程序以最大限度地提高性能

## Part A
编写三个`Y86-64`程序，通过参考`y86-code`文件夹中的参考代码`asum.ys asumr.ys`格式，完成`sum.ys rsum.ys copy.ys`的编写，在编写`copy.ys`中发现的问题是，基础的`Y86-64`指令集中，`addq subq` 只能跟着两个寄存器，因此要想进行立即数加减，需要首先通过`irmovq`将立即数放进寄存器中
## Part B
本质上就是要了解要添加到指令`iaddq` 在各个阶段的操作
- Fetch
    - icode:ifun ← M1\[PC]
    - rA:rB ← M1\[PC+1]
    - valC ← M8\[PC+2]
    - valP ← PC+10
- Decode
    - valB ← R\[rB]
- Execute
    - valE ← valC+valB
    - Set CC
- Memory
- Write Back
    - R\[rB] ← valE
- PC Update
    - PC ← valP
然后在 HCL 文件中对应位置增加`IIADDQ`即可
## Part C
- 首先明确一个概念：CPE(Cycles Per Element) 每个元素的时钟周期数，用来衡量循环代码执行效率，简单来说就是平均处理数组里的一个元素，CPU 需要花多少个时钟周期
本部分的核心就是优化程序，提高性能，整个 lab 最烧脑的地方！
由于 Part B 部分的设置，很容易想到使用`iaddq` 代替 `irmovq rrmovq` 仅仅这么操作 CPE 高达 11.70，得分 0 ！
面对循环，我们可以想到通过**循环展开**，通过增加每次迭代计算的元素数量，从而减少循环的迭代次数，同时在最初代码中`mrmovq (%rdi), %r10 rmmovq %r10, (%rdi)`存在数据相关，我们需要处理优化
- 循环展开：最容易想到的就是每次迭代把所有能用的寄存器全部使用，在 y86 中，除去`rsp rax rdi rsi rdx` 我们可以使用的寄存器一共10个，因此我们可以进行10 x 1循环展开，当10个一组全都处理过后，剩下的余数需要我们手动处理
- 余数处理： 对剩余数组元素的数目进行分类，通过`jl je jg` 进行跳转，通过构建三叉树寻找最优起点，从当前起点开始一直往回处理到第一个元素，倒叙处理余数
-  数据相关：对于`rmmovq mrmovq`的数据相关问题，我们 采取乱序执行，将本来的*读数据→判断→存数据* ，打乱变为*先检查上一个元素是否大于0，再读取当前元素，根据第一步的检查结果判断是否要增加 rax，最后在将当前数据写入目标数组中*
