# Data Lab (bits.c) 学习记录

## 一、实验规则理解

### Q1: Max ops 是什么含义？

每个函数头部注释中的 Max ops 表示该函数**允许使用的最大操作数**。

- 统计范围：整数运算（`~ & ^ | + << >>`）、逻辑运算（`!`）、比较运算
- `=` 赋值不计入操作数，可随意使用
- dlc 编译器会严格检查，超限则判定不合规
- 不同难度题目限制不同：简单题（如 bitXor 限制 14），难题（如 howManyBits 限制 90）

### Q2: `==` 等比较运算符允许使用吗？

**不允许。** 整数题目只允许 `! ~ & ^ | + << >>`，`==`、`!=`、`<`、`>` 等比较运算符都不在允许列表中。

替代方案：用 `^`（异或）判断相等 —— `a ^ a = 0`，`a ^ b ≠ 0`（不同值），配合 `!` 转换为 1/0。

### Q3: 整数题和浮点题的规则有什么区别？

| 规则   | 整数题                    | 浮点题            |
| ---- | ---------------------- | -------------- |
| 常量   | 仅 0~255 (0xFF)         | 任意整数/无符号常量     |
| 运算符  | 仅 `! ~ & ^ \| + << >>` | 任意整数/无符号运算     |
| 控制流  | 禁止 if/while/for 等      | 允许 if/while    |
| 数据类型 | 仅 int                  | int 和 unsigned |

## 二、逐函数解析

### 2.1 bitXor — 用 `~` 和 `&` 实现异或

**思路**：`x ^ y = (x & ~y) | (~x & y)`，但需要绕开 `|`。用德摩根律：`a | b = ~(~a & ~b)`

### 2.2 tmin — 返回补码最小值

**思路**：补码最小值位模式是 `1000...0000`。`1 << 31` 即可得到。仅需 1 个运算符。

### 2.3 isTmax — 判断是否为补码最大值

**思路**：Tmax = `0x7FFFFFFF`。关键性质：`Tmax + 1 = Tmin`，`~Tmax = Tmin`。利用 `!(x ^ 0x7FFFFFFF)` 的变体，结合 `x + 1` 后与 `~x` 比较。
需要注意的当 x = 0xFFFFFFFF 是我们也有 !(~x ^ (x + 1)) = 1，因此我们需要判断 !!t 保证 t 不为 0

### 2.4 allOddBits — 判断所有奇数位是否全为 1

**思路**：

1. **构造掩码**：`0xAA`（`10101010`）在 0~255 内，通过多次左移 8 位 + `|` 拼成 32 位的 `0xAAAAAAAA`
2. **检查**：`(x & mask) ^ mask` 若为 0 则说明奇数位全为 1，用 `!` 翻转结果

### 2.5 negate — 返回 -x

**思路**：补码下 `-x = ~x + 1`

### 2.6 isAsciiDigit — 判断 0x30 ≤ x ≤ 0x39

**方法一（差值符号位）**：用 `x + (~lower + 1)` 实现减法，检查符号位

**方法二（位模式匹配）**：
```c
int isAsciiDigit(int x) {
    int high4 = x >> 4;           // 高 4 位必须为 0x3
    int low4  = x & 0xF;          // 低 4 位
    int low3  = low4 & 0x7;       // 低 4 位去掉最高位 (bit 3)

    int checkA = !(high4 ^ 0x3);  // 高 4 位 == 0x3 ?
    int checkB = !(low4 & 0x8);   // bit3=0 → 范围 0~7，合法
    int checkC = !(low3 & 0x6);   // bit3=1 时 bit2,bit1 必须为 0
                                  // → 仅 1000(8) 和 1001(9) 合法
    return checkA & (checkB | checkC);
}
```

### 2.7 conditional — 用位运算实现 x ? y : z

**思路**：

- `flag = !x` → x 为 0 时 flag=1，x 非零时 flag=0
- `mask = ~flag + 1` → flag=1 得 `0xFFFFFFFF`，flag=0 得 `0x00000000`
- `(~mask & y) | (mask & z)` → x 非零取 y，x 为零取 z

```c
int conditional(int x, int y, int z) {
    int flag = !x;
    int mask = ~flag + 1;
    y = ~mask & y;  // mask=0 时保留 y
    z =  mask & z;  // mask=全1 时保留 z
    return y | z;
}
```

### 2.8 isLessOrEqual — 判断 x ≤ y

**思路**：计算 `y - x = y + (~x + 1)`，检查结果符号位。注意溢出情况（x 和 y 符号不同时单独处理）。
同号则直接进行运算，异号则判断x是否为负

### 2.9 logicalNeg — 实现 `!` 但不能用 `!`

**核心性质**：`x | (-x)` 对任意非零值（包括 tmin）结果的符号位必为 1；仅 x=0 时结果为 0。

```c
int logicalNeg(int x) {
    return ((x | (~x + 1)) >> 31) + 1;  // x=0→返回1; x≠0→返回0
}
```

### 2.10 howManyBits — 表示 x 所需的最少补码位数

**思路**：

1. **归一化**：负数取反 `x ^ (x >> 31)`，统一为正数处理
2. **二分查找最高位的 1**：逐级折半（16→8→4→2→1），用 `!!` + 移位判断每段是否有 1
3. **结果 +1**：补上符号位

```c
int howManyBits(int x) {
    int mask = x >> 31;
    x = x ^ mask;                    // 负数取~，正数不变

    int b16 = !!(x >> 16) << 4;      // 高16位有1？记16
    x = x >> b16;
    int b8  = !!(x >> 8)  << 3;      // 高8位有1？记8
    x = x >> b8;
    int b4  = !!(x >> 4)  << 2;      // 高4位有1？记4
    x = x >> b4;
    int b2  = !!(x >> 2)  << 1;      // 高2位有1？记2
    x = x >> b2;
    int b1  = !!(x >> 1);            // 高1位有1？记1
    x = x >> b1;
    int b0  = x;                     // 剩余那一位

    return b16 + b8 + b4 + b2 + b1 + b0 + 1;
}
```

### 2.11 floatScale2 — 浮点数 ×2 的位级实现

IEEE 754 单精度格式：`[符号 1bit][阶码 8bit][尾数 23bit]`

```c
unsigned floatScale2(unsigned uf) {
    unsigned s = uf & 0x80000000;
    unsigned e = (uf >> 23) & 0xFF;
    unsigned m = uf & 0x007FFFFF;

    if (e == 0xFF) {                  // NaN 或无穷
        return uf;
    }
    if (e == 0) {                     // 非规格化数
        m = m << 1;
        if (m & 0x00800000) {         // 尾数溢出进位
            e = 1;
            m = m & 0x007FFFFF;
        }
        return s | (e << 23) | m;
    }

    e = e + 1;                         // 规格化数
    if (e == 0xFF) {
        return s | 0x7F800000;         // 溢出变无穷
    }
    return s | (e << 23) | m;
}
```

## 三、位运算技巧总结

### 1. 逻辑判断类

| 技巧            | 表达式       | 说明                       |
| --------------- | ------------ | -------------------------- |
| 判断是否为 0    | `!!x`        | 非零→1，零→0               |
| 判断相等        | `!(a ^ b)`   | a==b→1, a!=b→0             |
| 全 0/全 1 掩码  | `~(!x) + 1`  | x=0→全0, x≠0→全1           |
| 提取符号位      | `x >> 31`    | 算术右移，负→全1，非负→全0 |
| 用 & 提取符号位 | `x & tmin()` | 负→0x80000000, 非负→0      |

### 2. 算术运算类

| 技巧         | 表达式              | 说明           |
| ------------ | ------------------- | -------------- |
| 取负         | `~x + 1`            | 补码下 -x      |
| 减法         | `a + (~b + 1)`      | a - b          |
| 乘以 2       | `x << 1`            | 左移 1 位      |
| 绝对值位操作 | `(x ^ mask) - mask` | mask = x >> 31 |

### 3. 位操作类

| 技巧        | 表达式               | 说明                 |
| ----------- | -------------------- | -------------------- |
| 提取低 n 位 | `x & ((1 << n) - 1)` | n=4 → 低 4 位        |
| 提取高 n 位 | `x >> (32 - n)`      | 取高 4 位：`x >> 28` |
| 置位        | `x \| (1 << n)`      | 第 n 位置 1          |
| 清零        | `x & ~(1 << n)`      | 第 n 位清 0          |
| 测试某位    | `!!(x & (1 << n))`   | 第 n 位是否为 1      |

### 4. 三段拼接（浮点）

符号、阶码、尾数三部分用 `|` 拼接：
```c
result = (s << 31) | (e << 23) | m;
// 或让符号位保持在原位：
result = s | (e << 23) | m;   // s 已经是 0x80000000 或 0
```

### 5. 常见坑

- **运算符优先级**：`+` > `<<`，位运算中别忘了加括号
- **移位越界**：移位量 < 0 或 > 31 时行为不可预测
- **常量限制**：整数题只能用 0~255，大常量需通过移位构造；浮点题无此限制
- **dlc 使用 C89 标准**：变量声明必须在所有可执行语句之前，不能混在代码中间声明
- **dlc 禁止强制类型转换**：`(int)` 等 cast 语法一律非法
- **整数题禁止 if 语句**：只能用 `! ~ & ^ | + << >>` 运算符组合实现控制流

## 四、2026-05-14 遇到的问题与解决

### 4.1 dlc 编译错误：变量声明位置 (C89)

**问题**：`bits.c:247: undeclared variable 'result'`，但明明声明了 `int result`。

**根因**：dlc 基于 C89 标准，要求所有变量声明必须放在代码块开头，在任何可执行语句之前。以下写法是 C99 风格，dlc 不支持：

```c
// 错误：声明在可执行语句之后
y = ~y + 1;
int result = x + y;
```

**修复**：将声明移到函数开头：
```c
// 正确：先声明所有变量，再执行
int result;
y = ~y + 1;
result = x + y;
```

**教训**：写 bits.c 时，每个函数的局部变量全部声明在函数体最前面。

### 4.2 dlc 报 Illegal cast

**问题**：`bits.c:402: floatFloat2Int: Illegal cast`

**根因**：dlc 禁止任何形式的强制类型转换。这是整数题编码规则第 6 条明文禁止的。`(int)abs` 和 `(unsigned)abs` 被 dlc 识别为非法操作。

**修复**：
- 避免 cast，用位运算实现类型转换等效逻辑
- `-(int)abs` 可替换为 `~abs + 1`（补码取负）
- floatFloat2Int 这类函数需要用掩码选择而非 if 判断

### 4.3 isLessOrEqual 与溢出判定

**问题**：`x - y`（即 `x + (~y + 1)`）在 x 与 y 符号不同时可能溢出。

**溢出条件**：`x > 0` 且 `y < 0` 时 `x - y` 向正溢出；`x < 0` 且 `y > 0` 时向负溢出。

**判定策略**：
1. **符号相同** → `x - y` 永不溢出，直接看差值符号位
2. **符号不同** → 不做减法，直接比较符号：x 为负则 x < y 必成立

```c
int isLessOrEqual(int x, int y) {
  int sx = x >> 31;
  int sy = y >> 31;
  int diffSign = sx ^ sy;          // 符号不同为 1
  int diff = x + ~y + 1;           // x - y（可能溢出）
  int same = !!((diff >> 31) | !(x ^ y));  // 同符号时 x<=y
  return (!diffSign & same) | (!!diffSign & !!sx);
}
```

**核心思想**：**符号不同时根本不需要做减法**。符号相同时做减法绝对安全。

### 4.4 isTmax 假阳性 bug（-1 被误判）

**问题**：`return !(~x ^ (x + 1));` 对 `x = -1` 和 `x = Tmax` 都返回 1。

**根因**：`~x == x + 1` 有两种情况成立：
- `x = Tmax (0x7FFFFFFF)`：溢出导致 `Tmax + 1 = Tmin = ~Tmax`
- `x = -1 (0xFFFFFFFF)`：代数恒等 `-1 + 1 = 0 = ~(-1)`

**修复**：添加 `& !!(x + 1)` 滤掉 -1（-1 + 1 = 0）：

```c
int isTmax(int x) {
  int t = x + 1;
  return !(~x ^ t) & !!t;
}
```

### 4.5 howManyBits 的 Tmin 与负 2 的幂问题

**问题**：原代码用 `(x + mask) ^ mask` 对负数求绝对值。但：
- `Tmin` 绝对值无法表示（`-Tmin = Tmin`），永远卡在 31
- `-8` 类 2 的幂负数给出错误结果 5，正确答案是 4

**根因**：`(x + mask) ^ mask` 等价于 `-x`（求绝对值），但 howManyBits 需要的不是绝对值，而是**与符号位不同的最高位位置**。

| x    | `-x` (旧) | `~x` (新)  | 旧答案 | 新答案 | 正确 |
| ---- | --------- | ---------- | ------ | ------ | ---- |
| -5   | 5         | 4          | 4      | 4      | 4 ✓  |
| -8   | 8         | 7          | **5**  | **4**  | 4 ✓  |
| Tmin | Tmin      | 0x7FFFFFFF | **31** | **32** | 32 ✓ |

**修复**：将 `x = (x + mask) ^ mask` 改为 `x = x ^ mask`，对负数取 `~x`：

```c
int mask = x >> 31;
x = x ^ mask;  // 正数不变，负数取 bitwise NOT
```

### 4.6 floatPower2 的边界与 denorm 遗漏

**问题**：
1. `if (x <= 0x8F)` — 常量 `0x8F = 143` 毫无意义，导致大量合法输入返回 0
2. else 分支直接 `return 0`，完全遗漏了非规格化数 (denorm) 区间
3. denorm 和 norm 边界不清晰

**修正后的完整实现**：
```c
unsigned floatPower2(int x) {
  if (x < -149)
    return 0;              // 太小：即使 denorm 的最小位也够不到
  if (x > 127)
    return 0x7F800000;     // 太大：超出最大规格化数 → +INF
  if (x >= -126)
    return (x + 127) << 23; // 规格化：e = x + 127, 尾数为 0
  return 1 << (x + 149);    // denorm: -149 ≤ x ≤ -127
}
```

**为什么 -149 是 denorm 的极限**：
```
denorm 值 = (fraction / 2^23) × 2^(-126) = fraction × 2^(-149)
我们是 2^x → fraction = 2^(x + 149)
fraction 最小为 1 → x + 149 ≥ 0 → x ≥ -149
```

### 4.7 btest 编译警告：arg_test_range 未初始化

**问题**：`btest.c:334:23: warning: 'arg_test_range' may be used uninitialized`

**根因**：`arg_test_range[3]` 仅当 `args == 3` 时才全部赋值，`args == 1` 或 `args == 2` 时 `[2]` 未初始化就被读取。这不影响你的 bits.c 正确性，只是 btest 工具本身的小缺陷。

**修复**：`int arg_test_range[3] = {0};` 加上初始化器即可消除警告。

## 五、关键原则回顾

### 1. 二进制搜索 (Binary Search)

howManyBits 采用的逐级折半模式是一种通用技巧，用于在对数时间内定位最高有效位：
- 16 → 8 → 4 → 2 → 1，每次判断高半段是否有目标位
- `!!(x >> n)` 将非零值归一化为 1，适配移位长度计算

### 2. 条件掩码 (Conditional Mask)

避开 if 的核心方法：
- `!!x` → 归一化为 0 或 1
- `~flag + 1` → 0→全0, 1→全1（符号扩展）
- `(mask & a) | (~mask & b)` → mask=全1 取 a，mask=全0 取 b

### 3. 符号处理模式

- **提取符号**：`x >> 31`（算术右移，全 0 或全 1）
- **取绝对值**：`(x ^ mask) - mask` 或 `(x + mask) ^ mask`（后者对 Tmin 失效）
- **按符号分情况**：正/负数不同算法，用掩码选择结果

### 4. IEEE 754 浮点布局

单精度 32 位 = `[s:1] [e:8] [f:23]`，偏置 = 127
- **NaN/Inf**：e = 0xFF
- **Denorm**：e = 0，隐含前导 0，实际指数 = -126
- **Norm**：1 ≤ e ≤ 254，隐含前导 1，实际指数 = e - 127

### 5. 补码位数计算

需要的最少位数 = 「与符号位不同的最高位位置」+ 1
- 正数：最高 1 位的位置 + 1（加符号位 0）
- 负数：用 `~x` 找最高 0 位等效位置 + 1（加符号位 1）
