# Attack Lab
## 实验前置工具
- 对于汇编代码文件我们想要知道每一行指令对应的字节序列，`gcc -c foo.s`  会生成`foo.o` 文件，然后使用 `objdump -d foo.o` 就可以得到汇编指令对应的字节序列
> [!NOTE] ret
> `ret` 指令实际上分为两步，分别是`rip = *(uint64_t *)rsp` 和 `rsp += 8` 
## 实验思想
前三个阶段使用代码注入攻击(Code Injection Attacks)，后两个阶段使用返回导向变成(ROP)
## Phase 1
不注入额外的代码，只是通过缓冲区的溢出来实现`touch1`函数的调用，只需要用无效字符填充缓冲区，将`touch1`的地址写进栈的返回地址处即可
## Phase 2
调用`touch2`，同时需要将`cookie`作为输入传递，因此需要覆盖的返回地址是植入的命令的地址，即`getbuf`创建的缓存区的顶部地址，然后在第一次`ret` 的时候就能来到我们植入的指令处并执行，同时需要在编写的指令中将`touch2`的地址`push`进栈，从而在第二次`ret`的时候能够成功进入`touch2`
## Phase 3
将`cookie`转换为八位字符串，用`ascii`码表示，作为参数传入`hexmatch`中进行匹配，与传入数据不同，传入字符串需要传入首字符的地址，因此我们需要在缓冲区输入时将字符串的地址传入，同时我们需要保证该地址所在位置不会被`hexmatch`的`caller-safe`的压栈行为覆盖，因此我们可以把字符串储存在第一次`ret`后的栈顶，因为这个位置不会被压栈覆盖
## Phase 4
`rtarget`使用随机化技术，每次运行时的栈堆都不同，因此无法确定注入代码的具体位置，因此我们可以通过现有代码而非注入新代码完成任务，于是面向返回编程(ROP)诞生，我们抽取现有指令字符中我们需要的，通过`ret`的`c3`序列作为返回节点，生成一系列在栈中的指令
![[Pasted image 20260606172718.png]]
在这一阶段，我们同样需要跳转到`touch2`函数，但是由于无法从外部注入函数，我们该如何输入我们的`cookie`？这是我们可以使用`pop`将存储在栈上的`cookie`输入给现有的寄存器，在转移给`%rdi`
## Phase 5
和 Phase 4 相似，但是问题是，我们需要知道我们注入的`cookie` 的字符串的位置，由于绝对位置在每次程序运行时都会变，我们可以采用相对位置，即`rsp + [偏移量]`进行，我们将字符串放置在`touch3`地址的下一个，同时由于可用指令的限制，我们需要借用不同的寄存器进行跳转，完成对`%rdi`的赋值，具体思路是：
1. 拿到 `%rsp` 指向的地址
2. `地址 + 偏移量` 到 `%rdi`
3. 调用`touch3`
4. `cookie`放置在`stack`最后面
5. 字符串结尾加上`\0`
```asm
movq %rsp, %rax
movq %rax, %rdi
pop %rax
constant 0x48
movl %eax, %edx
movl %edx, %ecx
movl %ecx, %esi
lea (%rdi, %rsi, 1), %rax
movq %rax, %rdi
touch3 的地址
cookie 字符串
```
